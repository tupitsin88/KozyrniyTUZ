# Сервис клубного членства

Сервис объединяет несколько клубов. Аккаунт с глобальной ролью User создаёт клуб или подаёт заявку в существующий, видит свои клубы в профиле и читает их материалы.

Создатель с глобальной ролью User получает дополнительное полномочие Administrator своего клуба. Administrator рассматривает заявки, добавляет и удаляет участников, обновляет материалы своего клуба. SuperUser архивирует клубы и не получает полномочия Administrator.

## Доступ к материалам

В сервисе есть один тег: club-member. Он привязан к конкретному пользователю и конкретному клубу.

Тег club-member для клуба «Кино» открывает все материалы клуба «Кино». Он не открывает материалы других клубов. Пользователь может иметь этот тег в нескольких клубах.

Архивированный клуб скрывается из списка, а доступ к его материалам прекращается. Его данные сохраняются.

## Роли

| Роль | Возможности |
| --- | --- |
| User | Создаёт клубы, подаёт заявки, видит профиль и свои заявки |
| User + Administrator клуба | Сохраняет действия User и управляет заявками, участниками и материалами своего клуба |
| SuperUser | Архивирует клубы; не создаёт клубы и заявки; видит ранее созданные собственные заявки |

## Стек

- Go для сервера;
- TypeScript для браузерного клиента;
- PostgreSQL для хранения данных;
- HTTP и JSON для обмена между клиентом и сервером.

Для запуска API требуется поддерживаемый PostgreSQL 15 или новее. При старте сервер проверяет подключение и применяет ещё не выполненные SQL-миграции. CI проверяет интеграционные сценарии на PostgreSQL 15 и 18. По умолчанию сервер доступен только на этой машине через `127.0.0.1`; сетевой адрес задаётся явно через `LISTEN_HOST`. Пошаговый запуск, создание локальных баз и настройка интеграционных тестов описаны в [PROJECT.md](PROJECT.md#10-локальный-запуск).

## Статус

Go API подключается к PostgreSQL, применяет миграции и реализует регистрацию, вход, клубы, заявки, членство, материалы и архивирование. Браузерный интерфейс отдаётся этим же сервером и использует тот же origin. Команды запуска приведены в [PROJECT.md](PROJECT.md#10-локальный-запуск).

## Учётная запись и сессия

- `POST /api/register` создаёт только роль `User`, сразу выдаёт серверную сессию и CSRF-токен.
- `POST /api/login` проверяет пароль Argon2id, отзывает действующую сессию этого браузера при замене и выдаёт новые cookie и CSRF-токен.
- `GET /api/session` возвращает CSRF-токен текущей действующей сессии после перезагрузки страницы.
- `POST /api/logout` требует текущую cookie, CSRF-заголовок `X-CSRF-Token` и точный `Origin`; повторный выход безопасен.

Регистрация и вход принимают JSON. Изменяющие запросы требуют `Origin`, совпадающий с `TRUSTED_ORIGIN` (по умолчанию `http://localhost:8080`). Пароли должны иметь длину от 12 до 1024 байт; имя входа — от 3 до 64 ASCII-символов: буквы, цифры, точка, дефис или подчёркивание. Для первой установки пустая база требует `BOOTSTRAP_SUPERUSER_LOGIN` и `BOOTSTRAP_SUPERUSER_PASSWORD`.

Подробная граница продукта, сценарии и правила доступа описаны в PROJECT.md. Связи требований, угроз и решений с автоматизированными тестами и известными пробелами перечислены в [VERIFICATION.md](VERIFICATION.md).

## Браузерный интерфейс

После запуска сервера откройте `http://localhost:8080`. Для входа используйте обычный аккаунт или bootstrap SuperUser. Интерфейс не хранит bearer-токены: сессию устанавливает `HttpOnly` cookie, а CSRF-токен остаётся в памяти страницы. Действия и доступ к данным всё равно проверяются Go API.
